### DOOM Developer Vocabulary: A Comprehensive Dictionary

To a modern C or Java developer, the DOOM codebase can feel like reading a foreign language. This dictionary is designed to help you decode the specific vocabulary, abbreviations, and metaphors used by the original id Software team.

---

### 1. The "High-Level" Lexicon (Subsystems)

Most global symbols start with a 1- or 2-letter prefix. This is the "namespace" of the developer.

| Word | Context | Meaning |
| :--- | :--- | :--- |
| **D_** | **Doom** | The high-level coordination and entry point. |
| **R_** | **Refresh** | The rendering/refresh system. |
| **P_** | **Play** | The "playsim" (game logic, physics, AI). |
| **W_** | **WAD** | The resource management system (WAD = "Where's All the Data?"). |
| **I_** | **Interface** | The system/portability layer (Input, Video, Sound). |
| **V_** | **Video** | Low-level screen buffering and graphics primitives. |
| **Z_** | **Zone** | The custom memory allocator. |
| **M_** | **Misc** | Miscellaneous utilities (Menu, Math, Parameters). |
| **G_** | **Game** | Game state management (Save/Load, Demos). |
| **S_** | **Sound** | The sound engine. |

---

### 2. Core Domain Nouns (The DOOM "Objects")

These are the fundamental entities that make up the game world.

| Word | Origin | Meaning |
| :--- | :--- | :--- |
| **Mobj** | **Map Object** | Any dynamic entity in the world (Player, Monster, Rocket, Health pack). |
| **Tic** | **Time Unit** | 1/35th of a second. The "heartbeat" of the game logic. |
| **Lump** | **Data Entry** | A single entry inside a `.wad` file (a texture, a sound, a map). |
| **Sector** | **Area** | A convex polygon on the map with a specific floor and ceiling height. |
| **Seg** | **Segment** | A part of a wall that is visible to the renderer. |
| **Linedef** | **Line Definition** | A 2D line that connects two vertices, forming a boundary. |
| **Sidedef** | **Side Definition** | The texture and offset data for one side of a Linedef. |
| **Subsector** | **Leaf Node** | A small, convex part of a sector generated by the BSP tree. |
| **Patch** | **Image** | A 2D graphic used for walls or UI elements. |
| **Flat** | **Floor Texture** | A raw 64x64 image used for horizontal surfaces. |
| **Thing** | **Map Data** | An object placed on the map (monsters, ammo) in the `.wad` file. |

---

### 3. Common Verbs (The "Action" Functions)

If you see these in a function name, they always mean the same thing:

| Word | Meaning | Example |
| :--- | :--- | :--- |
| **Init** | One-time setup during startup. | `R_Init` |
| **Ticker** | Logic update function (runs 35 times a second). | `P_Ticker` |
| **Drawer** | Rendering function (blits pixels to the screen). | `ST_Drawer` |
| **Responder** | Input handling function (responds to keys/mouse). | `M_Responder` |
| **Setup** | Prepares variables for a specific task or frame. | `R_SetupFrame` |
| **Add** | Pushes an item into a list or rendering queue. | `R_AddLine` |
| **Check** | A conditional test or query. | `M_CheckParm` |
| **Store** | Finalizes and saves a result into a data structure. | `R_StoreWallRange` |

---

### 4. Cryptic Rendering Vocabulary

The renderer uses specialized shorthand for geometry and clipping.

| Abbreviation | Full Term | Meaning |
| :--- | :--- | :--- |
| **yl / yh** | **Y Low / Y High** | The vertical screen coordinates (bottom and top). |
| **x1 / x2** | **X Range** | The horizontal pixel boundaries of a segment. |
| **rw_** | **Render Wall** | Variables used for calculating wall projections. |
| **ds_** | **Draw Seg** | Variables related to a visible wall segment. |
| **dc_** | **Draw Column** | Parameters for drawing vertical columns of pixels. |
| **vis** | **Visible** | Anything currently being considered for rendering (e.g., `visplanes`). |
| **bbox** | **Bounding Box** | A rectangle (Top, Bottom, Left, Right) used for quick collision tests. |
| **Fixed** | **Fixed-Point** | 16.16 integer math. |

### 6. Memory & Technical "Slang"

| Term | Context | Meaning |
| :--- | :--- | :--- |
| **PU_** | **Purge Unit** | Tags for the `Z_Zone` allocator (`PU_STATIC`, `PU_CACHE`, `PU_LEVEL`). |
| **FixedMul** | **Fixed Multiply** | Multiplying two fixed-point numbers with bit-shifting. |
| **validcount** | **Sync Marker** | A globally incremented counter used to avoid processing the same object twice in one frame. |
| **shm** | **Shared Memory** | Related to X11/System V shared memory for video. |
| **ev_** | **Event** | Input events (keydown, mousemove, etc.). |

---

### Analyst's Tip for Newbies:
When you see a one-letter variable in DOOM (like `p`, `s`, or `l`), its meaning is almost always tied to the function's prefix.
- In `P_` (Playsim) functions, `p` is usually a `player_t*`.
- In `R_` (Renderer) functions, `s` is often a `seg_t*` or `sector_t*`.
- In `W_` (WAD) functions, `l` is usually a `lump_t`.

Knowing the **Context** is the key to decoding the shorthand!
